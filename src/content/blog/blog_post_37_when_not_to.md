# When to Design a Prestige (and When Not To)

The instinct when a player develops a distinctive specialization is to reward it with mechanics. I've learned to distrust that instinct, because writing rules for something a player was already doing well can take it away from them.

Here's the failure mode. A character has been the group's negotiator for a year — not because of a proficiency, but because that player enjoys it and is good at it. So I write them a prestige class with bonuses to social checks and a once-per-week ability to read a room. Sounds like a reward.

What actually happens is that the thing stops being theirs. It was an identity built out of choices at the table; now it's a feature with a recharge. Worse, it becomes measurable, which means it can fail on a die roll in a way it never could before, and the player who used to _just talk_ is now rolling against a DC to do the thing they were previously simply known for. I've made their best quality into an ability that sometimes doesn't work.

So the first test I apply is: **is this specialization currently limited by anything?** If a character is already doing the thing reliably and the fiction supports it, mechanics add nothing but a failure chance. Leave it alone. Some of the strongest characters I've run for have zero mechanical support for the thing everyone remembers them for.

The second test is: **does the world need a name for this?** A prestige class in my setting is a recognition — it means enough people have done this that the practice has a name and, usually, someone who could teach it. That works for the Rüzgar because wind pacts are an established tradition with other practitioners in it. It doesn't work for a specialization that exists because one particular character made one particular set of choices. There is no school for being _that person_. Building a class implies a lineage that doesn't exist.

The third test is the practical one: **would this be interesting to a second character?** If the answer is no — if the whole thing only makes sense for the exact character who inspired it — then what I have isn't a prestige class. It's a description of somebody. Writing it as a class is a category error, and a slightly sad one, because it implies the character is a build rather than a person.

What I do instead in those cases is give them something with no mechanics attached at all. A title people use. A reputation that opens specific doors. An NPC who seeks them out because of it. A standing invitation somewhere. Those cost nothing to adjudicate, can't fail on a roll, and cannot be replicated by anyone else — which is exactly what makes them feel like recognition rather than an upgrade.

The clearest signal that something _should_ become a prestige is when I notice I'm improvising the same ruling repeatedly for different characters. Not one player's thing — several people converging on the same behaviour, and me deciding by feel each time how it works. That's a gap in the rules with real demand behind it. That's where Glyph-Breaker came from, and Margin Walker: several characters kept trying to defend against systems the rules only described offensively, and I was making it up every time.

The opposite signal is when a player asks for one. Not always, but often enough to be a rule of thumb — a request for a prestige class is frequently a request for permission, and the honest answer is usually that they don't need permission because nothing is stopping them. Kazankor has no class gatekeeping. If a character wants to do the thing, they do the thing. Writing it into a class can accidentally communicate the opposite: that it wasn't real until it had a stat block.

There's a cost to holding this line, and it's real. Players like getting things, and "you're already doing it, I don't need to write anything" is a less satisfying answer than a new page for their sheet. I've had that land badly. What I try to do now is say plainly what I'm protecting — that the thing they built stays theirs, unmeasured — and then give the recognition in fiction instead, immediately and visibly, so it doesn't read as me withholding a reward.

The test that covers all of it: mechanics should describe what a character _can_ do, not certify what they already _are_. When I catch myself writing a class as certification, I stop and give them a title instead.
